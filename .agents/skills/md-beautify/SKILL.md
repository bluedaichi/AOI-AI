# ノートを見やすく整える

目的：スマホの Obsidian で開いて、**スクロールせずに「結論」と「次にやること」が分かる**ノートにする。
中身（事実・数字・リンク・出典）は変えない。変えるのは並べ方と見せ方だけ。

## 書式のルール

### 1. 先頭の並び（この順番で固定）
```
---
created: YYYY-MM-DD
updated: YYYY-MM-DD
tags: [...]
status: 進行中 | 完了 | 下書き | 参考
---
# タイトル

> [!summary] 結論
> 1〜3行。何のノートで、答えは何か。

> [!todo] 次にやること
> - [ ] 担当（本人／AI）つきで、最大3つ

（本文）

## 出典
## 関連
```
- 「次にやること」がないノート（資料など）は、todo を省く。

### 2. コールアウトの使い分け（Obsidian の `> [!種類]`）
| 種類 | 使う場面 |
|---|---|
| `[!summary]` | 結論（各ノートに1つ） |
| `[!todo]` | 次にやること |
| `[!warning]` | 耳の痛い指摘、リスク、注意 |
| `[!question]` | 本人に確認したいこと、未確認のこと |
| `[!tip]` | おすすめ |
| `[!info]-` | 細かい補足。末尾に `-` を付けると**折りたたみ**になる |

### 3. 表は3列まで
- スマホで横スクロールが出ないように、表は**3列以内**、1マスは**全角10字前後まで**にする。
  - 長い名前は略す（例：「箱根モビリティサービス（登山ハイヤー）」→「箱根モビリティ」）。正式名はカードの見出しに書く。
  - 1マスに文を入れない。説明が要るものは表に入れず、カードか箇条書きにする。
- 見出しも短くする（全角15字前後まで）。所在地などの補足は見出しに入れず、カードの1行目（**場所**：…）に書く。
- 出典の列は作らない（脚注にする）。
- 4項目以上を比べるときは、**カード型**にする：
  ```
  ### 会社名　◎おすすめ
  - **副業**：可（届出制）
  - **年収の目安**：450万〜
  - **注意**：…
  ```
- カードの前に、3列の早見表（名前／評価／ひとこと）を置く。

### 4. 文と箇条書き
- 見出しは `##` が基本。`###` はカードや小分けにだけ使う。`####` は使わない。
- 箇条書きは1項目1〜2行。長くなったら分ける。
- 太字は1項目に1か所まで（ラベルか、一番大事な数字）。
- 数字は半角、単位つき。比べるときは差も書く（例：今より **+120万円**）。
- 評価記号は ◎（おすすめ）○（よい）△（要確認）×（合わない）に統一する。
- 絵文字は使わない（アイコンはコールアウトに任せる）。

### 5. 出典
- 本文にURLを並べない。脚注を使う：本文に `[^1]`、末尾の `## 出典` に `[^1]: [サイト名](URL)（確認日・掲載日）`。
- 1つの項目で同じ出典を何度も使うときは、同じ番号を使い回してよい。

### 6. 長い資料
- 補足、計算の過程、古い情報は `> [!info]- 詳細` に入れて折りたたむ。
- 流れや手順は、必要なら Mermaid の図（`flowchart`）にする。ただし5ステップ以下のときだけ。

## 既存ノートを整える手順
1. 対象ノートを読む。そのセッションで自分が作ったノート以外は、**整え方の方針を3行で示して了承を得る**（AGENTS.md「既存ノートの書き換え」）。
2. 上の書式で書き直す。事実・数字・URL・[[リンク]] は1つも消さない、変えない。
3. 書き直す前の版が git に保存されていることを確認する（未保存なら `git add` → `git commit` してから書き直す）。
4. チェックを実行する：
   ```
   bash .agents/skills/md-beautify/check.sh <ノートのパス>
   ```
   直前の保存版と比べて、消えた URL・[[リンク]]・数字を表示する。「OK」以外が出たら、本文に戻すか、消してよい理由を本人に伝える。
5. `updated:` を今日の日付にする。
6. 変えた点を2〜3行で本人に伝える（例：「6列の表を、会社ごとのカードに分けました」）。

## 書式に合わないノートを探す
```
bash .agents/skills/md-beautify/lint.sh            # 対象フォルダ全体
bash .agents/skills/md-beautify/lint.sh <パス>     # 1つだけ
```
- 対象：10_Projects・20_Areas・30_Resources（30_Resources/me と 10_Projects/*/drafts は除く）
- frontmatter に `beautify: false` があるノートは対象外
- 自動化：保存のたびに `.claude/hooks/check-format.sh` がこれを実行し、合わなければ整えるよう促す。定期実行「vault-auto-beautify」（毎日 9・12・15・18・21時）が残りを整える

## 新しいノートを書くとき
最初からこの書式で書く。チェック（手順4）は不要。

## やらないこと
- 内容の追加・削除・言い換え（誤字の修正は可。直したら伝える）
- 本人が書いた文章の言い回しの変更（並べ替えとコールアウトで囲むことだけ）
- 問い合わせ文・メール文など、**そのままコピーして使う文面**の中身への装飾（文面の外に要約と todo を足すだけにする）
