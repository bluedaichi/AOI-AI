# note-draft：記事の下書き

> [!summary] 何をするスキルか
> note の記事を、**企画 → 構成 → 本文**の順に一緒に作り、`10_Projects/note-shueki/drafts/` に下書きを残す。公開はあなたが行う。

## 呼び出し方
| 場面 | 言い方の例 |
|---|---|
| メモを記事に | 「このメモを note にしたい」 |
| 下書きがほしい | 「〇〇の記事を下書きにして」 |
| 名前で呼ぶ | `/note-draft` |

## 使うとどうなるか
1. **企画**：誰に向けた記事か、読者が得るもの、無料か有料かを確かめます → 「OK」と返す
2. **構成**：タイトル案3つと見出し4〜7個が届きます → 「OK」と返す
3. **本文**：あなたの体験・数字・失敗談を中心に、[[文体ガイド]] に沿って書きます
4. **レビュー**：別の AI（Codex）が、約束を果たせているか・事実は正しいかを確かめ、指摘を反映します
5. 完成すると `status: ready` になり、progress.md に1行足されます

> [!warning] 書かないこと
> - あなたが言っていない実績や収益の数字（盛らない）
> - 勤務先や職場の人が分かる内容
> - 他の人の記事・本の文章の写し

## 変わる前と後（例）

> [!example]- 前：00_Inbox のメモ
> 「動画マニュアルを全社に入れたときの話、記事にできそう」

> [!example]- 後：下書きファイルができる

> ```
