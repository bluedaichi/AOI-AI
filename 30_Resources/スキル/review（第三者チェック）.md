# review：第三者チェック

> [!summary] 何をするスキルか
> 書いた本人とは**別の AI（Codex）**が文章を評価し、指摘を `_agent/Reports/` に書く。対象のファイルそのものは直さない。

## 呼び出し方
| 場面 | 言い方の例 |
|---|---|
| チェックしたい | 「〇〇をレビューして」 |
| 確かめたい | 「〇〇をチェックして」 |
| 名前で呼ぶ | `/review 〇〇.md` |

- note の記事、公開する文章、お金が絡む資料は、書き終えると**頼まなくても**この流れになります（CLAUDE.md のルール）。

## 使うとどうなるか
1. Claude が `_agent/Tasks/` に依頼書（何を・どの観点で）を書きます
2. Codex が対象を最後まで読み、5つの観点で評価します
   - 目的・正確さ（計算は検算）・抜け漏れ・分かりやすさ・リスク
3. `_agent/Reports/` に結果が届きます
4. Claude が指摘を反映するかを決め、その理由を短く伝えます

## 結果の形
| 項目 | 中身 |
|---|---|
| 判定 | OK／要修正／作り直し |
| 必ず直す点 | 箇所・問題・修正案 |
| 良くなる点 | 任意の改善 |
| 良い点 | 1〜2個 |

## 変わる前と後（例）

> [!example]- 前：書いた本人（AI）だけが確かめている

> [!example]- 後：Reports に指摘が届く
> ```
> # レビュー結果：2026-10-10-video-manual.md
> 判定：要修正
> ## 必ず直すべき点
> - 箇所：見出し3 / 問題：導入期間の数字が冒頭と違う / 修正案：どちらかに統一
> ```
